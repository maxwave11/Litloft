## Findings

### F1 [introduced] Page shortcuts stay live under the open dialog (Ctrl+C hijacked and the dialog closes; Ctrl+V and Ctrl+N write)
- `frontend/src/components/markdownExport/MarkdownExportContainer.tsx:64-70`. `useShortcuts("markdown-export-dialog", …, true, OVERLAY_PRIORITY)` is called without `blocksLower`. `lib/shortcuts.ts` documents `blocksLower` as "for something that covers the page: every context of a lower priority is out of reach while this one is open, so a key never acts on what the reader cannot see". The full-screen viewers (`EpubPreview`, `ImageGallery`, `PdfFullscreenViewer`) pass `true`.
- What a user hits: the document is shown as plain text in `<pre>`. The user selects text there (or hits the manual-copy fallback after "Could not copy") and presses Ctrl+C. `FolderBrowser.tsx:315-345` still has the `ctrl+c` handler. `ShortcutsProvider` calls `preventDefault()` on the match, so the native text copy never happens. The handler puts the file selection on the in-app clipboard, calls `selection.clear()` and `setSelectable(false)`. `SelectionBar` then returns null at `count === 0`, so the whole dialog unmounts and the assembled document is lost. Ctrl+X does the same with cut. Ctrl+V pastes the in-app clipboard into the folder behind the dialog, and Ctrl+N creates a file there (both guarded only by `isWriteDestination`). These are writes while the dialog is open.
- Reproduction: temporary vitest, since deleted. It rendered the real `ShortcutsProvider`, a stand-in `useShortcuts("file-browser", …, [{key:"ctrl+c", handler: spy}])` and `MarkdownExportContainer` with `files=[]`, then dispatched keydown Ctrl+C on `document.body`. Result: `LOWER_CALLED 1 PREVENTED true`. Adding `blocksLower=true` (M32) made no existing test fail, so no test holds this. [introduced]: the Container is a new file.
- Touches: invariant "Exporting writes nothing" (Ctrl+V and Ctrl+N paths); the dialog's own usability; `lib/shortcuts.ts` `blocksLower` contract. Not a prior-declared invariant for Ctrl+C itself.

### F3 [introduced] TOC anchors do not match GitHub's slugging for common titles
- `frontend/src/components/markdownExport/document.ts:74` `anchorOf`, whose doc comment says "GitHub's heading anchor". It strips everything outside `[\p{L}\p{N}\s-]` and then collapses whitespace with `\s+` to one `-`.
- Differences from GitHub's slugger, which I know from its algorithm because `github-slugger` is not installed here and I could not run it: GitHub keeps `_`, keeps `\p{M}` marks, and turns each space into one `-` without collapsing, so a removed punctuation character between two spaces leaves `--`.
- Observed output from `buildExportDocument`:
  - title "Cats | Dogs": link `#1-cats-dogs`. GitHub heading id is `1-cats--dogs`.
  - title "foo_bar": link `#2-foobar`. GitHub is `2-foo_bar`.
  - A title with a combining mark (decomposed Japanese dakuten U+3099, Thai or Devanagari vowel signs): the mark is stripped by `\p{M}`'s absence from the allow-list. GitHub keeps it.
- What a user hits: for any title containing `|`, `&`, an en dash with spaces, `_`, or combining marks, the TOC link in the copied document does not resolve to its own video's heading when the paste is rendered by a GitHub-style renderer. The in-app dialog shows plain text, so only the pasted document is affected. The tests cover only plain words and brackets (`1-part-1-of-two`, `1-same`).
- Touches: invariant "Every TOC link resolves to its own video's heading, including when two videos share a title". The number prefix does keep equal titles apart, and that part holds.

### F4 [introduced] The original-link text is written into the metadata line without escaping, so a newline in it forges document structure
- `frontend/src/components/markdownExport/runExport.ts:26` returns any non-empty string from the `.loft` JSON. `document.ts:96` does `parts.push(entry.originalUrl)` with no `oneLine` and no neutralising, unlike titles, labels and tags.
- Reproduced with `buildExportDocument` on a `.loft` whose `url` was `"https://x/\n\n## 9. Injected\n\n### YouTube comments\n- [AUTHOR] @me · 1 likes\n  > buy now"`. The output for video 4 contained, inside the `_…_` line, a `## 9. Injected` heading, a `### YouTube comments` heading and a line `- [AUTHOR] @me · 1 likes` followed by a quoted "buy now". That reads as a section with an author-tagged comment, in a document pasted into an AI.
- Who can write the `url`: whoever can create a `.loft` (clip import, upload, or MCP `upload_file`). It needs no comment text. A URL with spaces or `*`, `]` or `(` is also unescaped.
- Touches: invariant "No comment text can make a line read as written by the video's author" (this path is not comment text, but it produces the same forgery in the same document). Tags, titles and labels do go through `oneLine`; I checked a tag `"x\n## evil"` and it collapses to `#x-##-evil`.

### F5 [introduced] A section whose markdown is blank counts as a section: the video is included with an empty heading and no warning
- `frontend/src/components/markdownExport/document.ts:17` `hasSection` and `buildExportDocument` treat any `kind:"section"` as content. `outcome.markdown.trim()` can be `""`.
- Reproduced: a provider returning `{kind:"section", markdown:"   "}` produced `## 5. x\n\n### Transcript\n\n` (an empty `### Transcript`), the video is in the TOC and the count, and `exportGaps` reports nothing.
- Touches: invariant "When anything is missing … the viewer is warned" and "videos with no section are omitted". The provider contract says to answer `empty`, so this is a core robustness gap, not a documented misuse.

### F7 [introduced] No focus management for an `aria-modal` dialog (read from the code; not measured in a browser)
- `MarkdownExportPresenter.tsx:56-60`. Only the warning phase's Continue has `autoFocus` (line 144). In the building and document phases focus stays on the "Export" action in the bar under the scrim. There is no trap, so Tab walks into the page behind it, and nothing returns focus on close. The Escape shortcut is registered through `useShortcuts` (no focus requirement), so Escape works.
- `ConfirmDialog.tsx` focuses its confirm button and also has no trap. So this matches the precedent in spirit, but `aria-modal="true"` claims more than the page delivers.

### F8 [introduced] A stray backdrop click discards the finished document
- `MarkdownExportPresenter.tsx:53` `onClick={onClose}` on the scrim in every phase, including the finished document (before Copy) and the warning. Reopening re-runs `runExport` (a fetch per transcript). Same as `ConfirmDialog`'s behaviour, but here the cost is a rebuild. Low.

### F9 [introduced] Spec and code disagree on what Continue gives with no provider
- Spec "Button": "Shown even with no provider: the warning then says no sections are available, and Continue gives titles and metadata only". Spec "Document shape": "A video with no section at all is left out, TOC included". The code follows the second. With no addon, Continue shows "Nothing to export." and a Copy button that copies only `# Export: 0 videos`. Question for the author: which is intended? The spec's "Checked, no action" does not cover it.
- Also: the title says "N videos" while audio files are included.

### F10 [introduced] `Gap` `unregistered` carries a label in a field named `id`; the label is the raw manifest label
- `MarkdownExportContainer.tsx:86` `unavailable: notOffered.map((e) => e.label)`, `document.ts:11` `{ kind: "unregistered"; id: string }`, `gapLines.ts` `t("gapUnavailable", { name: gap.id })`. The name misleads a reader. `AddonSlot` renders tabs through `slotEntryLabel(entry, tGlobal)` using `i18n_key`; this path uses `entry.label` as is, so a Japanese viewer may be told "利用できません: <English label>". The spec says "names the entry's manifest `label`", so the label itself is intended; the field name is the issue.

### F11 [introduced] `selectedFiles` is rebuilt on every render while selecting
- `frontend/src/components/FolderBrowser.tsx:710` `files.filter((f) => selection.selectedIds.has(f.id))` runs on each `FolderBrowser` render in select mode, with a new array each time (O(loaded files)). Not measured; low.

### F12 [introduced] Hard-coded `", "` list separator and untranslated joiner in gap lines
- `gapLines.ts:10` joins titles with `", "`; the "and N more" is appended with a space. Japanese titles are joined with an ASCII comma. Low, i18n polish. No plural problem found: `documentTitle` uses ICU plural (ja `other` only), and the other count messages read correctly for 1.

Late provider after the plan is reported as unavailable, as designed. A provider registered by another mount is shared by id. Abort on unmount is held by a test (M20 killed). Selection frozen at open is held (M19 killed).
- Drive boundary: `drive` is the page's `driveName`; `FileItem.drive` exists but `runExport` does not check `file.drive === drive`. I found no path in `FolderBrowser` that lists another drive's files, so I report no defect, only the absence of a guard.
- Order: `files.filter` keeps list order; `FolderBrowser.exportSelection.test.tsx` holds it on four screens.
- Trash: the action is absent (`TrashView` passes no `selectedFiles`, and the test asserts it). The missing-files view has no `SelectionBar`.
